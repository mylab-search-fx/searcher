## Что в идее стоит сохранить

Клиент не пишет Query DSL. Индекс отделяет одну сущность от другой. Фильтр и сортировка — именованные ресурсы с аргументами. Ограничение из токена клиент не снимает своим запросом. Свободный текст и точные условия различаются. Стратегия `should` / `must` задаётся индексом, а не прячется в разборе строки.

Это нормальный фасад над поисковым движком. Его и стоит развивать.

## Где концепция расходится с задачей

Каталог фильтров — это и есть Elasticsearch. Файл фильтра хранит кусок Query DSL, а аргументы вставляются заменой `{from}` в тексте JSON. Клиентский контракт выглядит независимым, но автор фильтра пишет на языке движка. Смена версии DSL, типа поля или самого движка ломает каталог. Число и строка в аргументе неразличимы: шаблон решает, станут ли `"6"` числом. Ошибка в файле обнаруживается на запросе пользователя, а не при загрузке каталога. Общий каталог поверх каталога индекса легко подставляет одноимённый фильтр другому индексу.

Строка поиска совмещает несколько языков. Один литерал одновременно текст, число, дата, префикс и повод поднять релевантность.

- `100408` успешно читается и как целое, и как дата `ddMMyy`.
- `123-321` может быть диапазоном и обычным идентификатором.
- Голое `123` сравнивается с любым числовым полем: цена, количество и номер совпадут одинаково.
- `04/10/2008` разбирается как месяц/день, `10.04.2008` — как день/месяц.
- `int.TryParse` отсекает длинные идентификаторы и дробные значения.
- `regexp` вида `слово.*` по analyzed-полю `text` дорог и плохо совпадает с тем, как анализатор уже разрезал текст.
- Вес `число_слов - позиция` спорит со штатным ранжированием: в запросе «ошибка оплаты» слово «ошибка» важнее «оплаты» только из-за места в строке.
- Режим `should` с одним обязательным совпадением возвращает документ, где нашлось любое одно слово.

Повышенный вес полного совпадения со всей строкой — удачная часть. Её стоит оставить. Остальная грамматика делает поисковую строку непредсказуемой.

Токен поиска выпускает тот же сервис, который торчит наружу. Бэкенд уже решил, кто что может искать. Searcher только подписывает это решение ключом `SignKey`, лежащим на публичном процессе. Утечка ключа позволяет выписать любой индекс и любые аргументы фильтров. При выпуске не проверяется, что фильтр существует и что аргументы ему подходят. Без `ExpirySec` токен бессрочный, и срок при поиске тоже не проверяется. Отозвать токен нельзя. `*` открывает любой индекс. Токен добавляет обязательные фильтры, но не ограничивает, какие ещё фильтры клиент вправе назвать: любой файл из каталога доступен по имени.

Выдача и контракт не договорены. `offset`/`limit` уходят в `from`/`size`: глубокая страница упирается в лимит Elasticsearch и сдвигается, пока индекс меняется. Отладочные `esRequest` и `explanation` попадают в тот же ответ, что видит клиент. README, OpenAPI и журнал описывают разные формы: в README путь `/v4/indezes/...` и ответ-массив, в спецификации `/indexes/...`, объект с `entities` и поле `namespaces`, которое журнал уже переименовал в `indexes`.

## Чем заменять

Менять стоит механизм, не весь поиск.

Публичную точку поиска убрать, если браузер и так ходит в свой API. Бэкенд знает пользователя, подставляет обязательный фильтр и вызывает Searcher по приватной сети. Токен, `SignKey` и схема «приватный выпуск / публичный поиск» становятся лишними. Это лучшая замена, если отдельный открытый поиск не является требованием.

Файлы с подстановкой заменить на search template Elasticsearch, если готовы остаться на Query DSL. Шаблон хранится в движке, параметры типизированы Mustache, свой текстовый компилятор фильтра не нужен. Searcher остаётся тонким шлюзом: имя шаблона, параметры, индекс.

Сырой DSL заменить на типизированный предикат, если нужен свой стабильный язык. Фильтр описывает поле, оператор и тип параметра (`eq`, `range`, `terms`). Query DSL появляется только на выходе компилятора. Тогда каталог можно проверить по мэппингу на старте, а Elasticsearch позже сменить, не переписывая клиентов.

Разбор чисел и дат из строки заменить на отдельные аргументы. Свободный текст искать через `multi_match` и поле `search_as_you_type`: фраза, префикс, опечатка. `simple_query_string` подходит, если пользователям нужен явный синтаксис `поле:значение`. Самодельный regexp и календарь внутри строки для этого не нужны.

Обязательный фильтр «только мои заявки» вынести в filtered alias или document-level security, если ограничение — свойство документа: владелец, регион, организация. Тогда оно не ездит внутри JWT и не зависит от того, вспомнил ли бэкенд нужный id фильтра.

JWT заменить на непрозрачный токен, если публичная точка остаётся и права надо гасить раньше срока. Идентификатор токена лежит в хранилище вместе с политикой. Клиент не видит аргументы, отзыв — это удаление записи.

Другой движок (Typesense, Meilisearch) имеет смысл только если продукт — поле с подсказками по префиксу. Для нескольких индексов, именованных фильтров и принудительного сужения выборки смена движка задачу не снимает.

## Как я бы пересобрал концепцию

Searcher остаётся компилятором. Права живут снаружи. Каталог перестаёт быть папкой с Query DSL.

Запрос клиента выглядит так: текст, список id фильтров с типизированными аргументами, id сортировки, курсор и предел размера. Число и дата в текст не примешиваются.

Политика, если поиск всё же публичный, содержит три списка: доступные индексы, обязательные предикаты, разрешённые клиентские фильтры. Подписывает её бэкенд. Searcher проверяет подпись, срок и `jti`. Клиентский фильтр вне списка отклоняется. Обязательные предикаты клиент не выбирает и не переопределяет.

Фильтр в каталоге объявляет параметры и их типы. На старте сервис проверяет, что поле есть в мэппинге, тип сходится и обязательный параметр назван. Ранжирование оставляет повышенный вес у совпадения всей фразы. Вес по позиции слова уходит из ядра: если он нужен продукту, это отдельная настройка индекса.

Выдача идёт курсором. `limit` имеет потолок. Отладочный запрос в Elasticsearch доступен только внутреннему вызову. README и OpenAPI описывают одну форму ответа.

Порядок такой: сначала унести выпуск прав от публичного сервиса, затем перестать разбирать числа и даты из свободного текста, потом заменить текстовую подстановку типизированным каталогом и курсором.
